## 2024-05-15 - Managing Focus for Hidden Overlays
**Learning:** When building custom interactive cards with a hover overlay (like `OvenStatusCard` where the front face becomes `opacity-0` and the back face becomes `opacity-100` on hover or click), inner interactive elements (like the 'Close' button) inside the hidden overlay still receive keyboard focus if their `tabIndex` is not explicitly managed. This causes invisible elements to receive focus, confusing keyboard users.
**Action:** Always dynamically manage the `tabIndex` of interactive elements inside conditionally visible overlays (e.g., `tabIndex={isVisible ? 0 : -1}`). Additionally, ensure the main trigger element (the card itself) has `role="button"`, proper `onKeyDown` handlers for `Enter` and `Space`, and explicit `focus-visible` styles (`focus-visible:ring-2 focus-visible:ring-orange-500`) since custom components don't receive default browser focus styles.
